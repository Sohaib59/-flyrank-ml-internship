# The Plan to Keep Building

## 1. Where the next case study goes, and how to add one

**Location:** GitHub repo / GitHub Pages site — [add the exact path, e.g. `/case-studies/` folder
or `/docs/case-studies/` if that's what drives your Pages site — name the exact folder]

**The three-beat shape (reused from Week 2):**
1. **Problem** — what was broken or missing, in one or two sentences.
2. **What I did** — the real decision(s), not a feature list.
3. **What came of it** — the result, a number if you have one, or an honest "still in progress."

**Steps to add a new case, every time:**
1. Open the Claude Project (see §3) and paste in whatever you have: a README, a demo link, a few
   rough notes about what you built.
2. Ask it to draft the three-beat write-up in your existing voice — it already has your prior
   case studies as reference, so this is editing, not starting from a blank page.
3. Save the draft as a new file in [exact path — e.g. `case-studies/[project-name].md`].
4. Commit and push: `git add case-studies/[project-name].md && git commit -m "Add [project] case
   study" && git push`.
5. If your site is served via GitHub Pages, wait ~1-2 minutes and check the live page updated.

That's the whole loop — five steps, none of them "rebuild the site."
